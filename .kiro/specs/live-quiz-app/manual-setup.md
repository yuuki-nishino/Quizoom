# 人間が実施する作業一覧

AI エージェントが代行できない作業（アカウント作成、外部サービスの認可、シークレットの入力、ブラウザ操作を伴う設定）をまとめる。コード実装は全てエージェント側で行うため、ここに記載するのは**人間の手が必要な箇所のみ**である。

## 凡例

- **[必須]** — これが完了しないと実装または動作確認が進まない
- **[任意]** — なくても動作する
- **ブロックするフェーズ** — この作業が完了しないと着手できない工程
- **状態** — ✅ 完了 / ⬜ 未着手

---

## Phase A: 実装着手前

### A-1. Cloudflare アカウントの作成 [必須]

- **状態**: ✅ 完了
- **ブロックするフェーズ**: デプロイ、動作確認（ローカル開発のみなら不要）
- **手順**:
  1. https://dash.cloudflare.com/sign-up でアカウントを作成する
  2. メールアドレスの確認を完了する
  3. 支払い情報の登録は**不要**（Workers 無料プランのまま進める）
- **完了の確認**: ダッシュボードにログインでき、左メニューに「Compute (Workers)」が表示される

### A-2. Wrangler CLI のログイン [必須]

- **状態**: ✅ 完了
- **ブロックするフェーズ**: D1・R2・Durable Objects のリソース作成、デプロイ
- **手順**: ターミナルで以下を実行し、ブラウザで認可する。

  ```
  npx wrangler login
  ```

- **備考**: Claude Code のセッション内で実行する場合は、プロンプトに `! npx wrangler login` と入力すると出力がそのまま共有される
- **完了の確認**: `npx wrangler whoami` でアカウント名が表示される

### A-3. Google OAuth クライアントの発行 [必須]

- **状態**: ✅ 完了
- **ブロックするフェーズ**: 主催者ログイン機能の動作確認（要件1.1）
- **手順**:
  1. https://console.cloud.google.com/ でプロジェクトを作成する（既存プロジェクトの流用可）
  2. 「APIとサービス」→「OAuth 同意画面」を設定する
     - User Type: **外部**
     - アプリ名、サポートメール、デベロッパー連絡先を入力
     - スコープは `email` と `profile` のみ（追加スコープ不要）
     - 公開ステータスは「テスト」のままでよい。その場合は**テストユーザーに自分の Google アカウントを追加する**
  3. 「認証情報」→「認証情報を作成」→「OAuth クライアント ID」
     - アプリケーションの種類: **ウェブアプリケーション**
     - 承認済みのリダイレクト URI に以下を登録する

       | 環境 | URI |
       |------|-----|
       | ローカル開発 | `http://localhost:8787/api/auth/callback/google` |
       | 本番 | `https://<デプロイ先ドメイン>/api/auth/callback/google` |

  4. 発行された **クライアント ID** と **クライアントシークレット** を控える
- **注意**: 本番ドメインは A-5 の完了後に確定する。先にローカル用だけ登録し、後から追記してよい
- **完了の確認**: クライアント ID（`....apps.googleusercontent.com`）が手元にある

### A-4. シークレットの登録 [必須]

- **状態**: ⬜ 未着手
- **ブロックするフェーズ**: 認証機能の動作確認、本番デプロイ
- **重要**: シークレットの値を**チャットに貼り付けない**こと。会話ログに残る。以下のコマンドは対話的に値を入力する形式になっており、値が画面に出ない。
- **手順**: プロジェクトの初期構築（エージェント側で実施）が終わった後、以下を実行する。

  ```
  npx wrangler secret put GOOGLE_CLIENT_ID
  npx wrangler secret put GOOGLE_CLIENT_SECRET
  npx wrangler secret put BETTER_AUTH_SECRET
  npx wrangler secret put PARTICIPANT_TOKEN_SECRET
  ```

  - `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` — A-3 で控えた値
  - `BETTER_AUTH_SECRET` / `PARTICIPANT_TOKEN_SECRET` — ランダムな文字列。以下で生成できる

    ```
    openssl rand -base64 32
    ```

- **ローカル開発用**: 同じ値を `.dev.vars` に記述する（このファイルは `.gitignore` に含める。エージェント側で設定する）
- **完了の確認**: `npx wrangler secret list` に4件が表示される

## Phase B: デプロイ時

### B-1. リソースの作成確認 [必須・立ち会いのみ]

- **内容**: D1 データベース、R2 バケット、Durable Objects の名前空間を作成する
- **実施者**: **エージェントが CLI で実行する**（A-2 のログイン完了が前提）。人間は結果の確認のみ
- **人間の確認事項**: Cloudflare ダッシュボードで D1 と R2 が作成されていること

### B-2. 本番ドメインの確定と OAuth への反映 [必須]

- **ブロックするフェーズ**: 本番環境での主催者ログイン
- **手順**:
  1. 初回デプロイで `https://<worker名>.<サブドメイン>.workers.dev` が払い出される
  2. そのドメインを A-3 の「承認済みのリダイレクト URI」に追記する
  3. 反映まで数分かかる場合がある
- **完了の確認**: 本番 URL で Google ログインが完走する

### B-3. 独自ドメインの設定 [任意]

- **内容**: `workers.dev` のサブドメインではなく独自ドメインを使いたい場合
- **前提**: ドメインを取得し、Cloudflare のネームサーバーへ移管する（無料）
- **注意**: QR コードに埋め込まれる URL が変わるため、**印刷物を作る前に確定させる**こと。後から変えると配布済みの QR が無効になる
- **手順**: Cloudflare ダッシュボードで Workers のルートにドメインを割り当て、B-2 と同様に OAuth のリダイレクト URI を追記する

## Phase C: イベント開催前（運用）

要件12.3・12.4 に対応する、開催のたびに実施する確認作業。

### C-1. 事前動作確認 [必須]

- **タイミング**: 開催の**前日まで**に一度、および**当日の開始30分前**
- **手順**:
  1. 主催者アカウントでログインできること（Google の再認証が必要になっていないか）
  2. 進行画面から「事前確認」を実行し、3画面の疎通とリアルタイム配信が正常であることを確認する
  3. 自分のスマートフォンで実際に QR を読み取り、参加から回答までを1問通す
  4. 確認用に登録した参加者データを削除する
- **理由**: Cloudflare 構成にはプロジェクト自動停止がないため「動かない」リスクは低いが、**Google の認証期限切れ**と**会場ネットワークの制約**は当日まで判明しない

### C-2. 会場ネットワークの確認 [必須]

- **確認事項**:
  - 会場 Wi-Fi のゲスト向けパスワード有無と、同時接続数の上限
  - 投影用 PC が有線または安定した回線に接続できること
  - モバイル回線の電波状況（地下会場では特に要確認）
- **理由**: 参加者全員が同一 Wi-Fi に集中すると、アプリ側の性能に関わらず遅延する。人数によってはモバイル回線利用を案内したほうがよい

### C-3. 投影と配布物の準備 [必須]

- **確認事項**:
  - 投影用 PC の解像度が 16:9 で、ブラウザを全画面表示できること
  - スリープ・スクリーンセーバーを無効化すること
  - QR コードを印刷して配布する場合は、B-3 のドメイン確定後に出力すること
- **備考**: 投影画面の待機状態に QR コードが表示されるため、印刷は必須ではない

以下は人間の作業ではない。境界を明確にするために記載する。

- D1 のスキーマ定義とマイグレーション作成・適用
- D1 / R2 / Durable Objects のリソース作成コマンド実行（A-2 完了後）
- アプリケーションコードの実装とテスト
- デプロイコマンドの実行
- `.gitignore` と `.dev.vars` の整備
