# Implementation Plan

- [ ] 1. 基盤: 選択肢画像のデータ基盤と共有定義
- [ ] 1.1 選択肢画像の保存先と共有型の拡張
  - 選択肢ごとに画像の参照(0または1枚)を保存できるようデータベースを拡張し、既存の選択肢は画像なしとして扱われるようにする
  - 開催中の設問の選択肢情報、およびWebSocketで配信する設問の公開表示用データに、選択肢ごとの画像参照を追加する
  - 固定のテスト問題の選択肢が、新しい型に沿って画像なしとして定義されている状態にする
  - ローカルのデータベースへマイグレーションを適用でき、型チェックと既存テストが引き続き通ることを確認する
  - _Requirements: 6.1, 6.2_

- [ ] 1.2 画像仕様の定数と「選択肢画像を持つ設問」の判定
  - 画像の固定アスペクト比(4:3)・長辺の上限(800px)・出力形式(JPEG、品質0.85)を、クライアントとサーバーの双方から参照できる1か所に定義する
  - いずれかの選択肢が画像を持つ設問かどうかを判定する純粋な関数を用意する
  - 画像あり・なし・混在の各ケースで、判定結果が期待どおりになる単体テストが通る
  - _Requirements: 2.1, 2.2, 3.4, 3.6_

- [ ] 2. コア: サーバー側の保存・スナップショット・配信
- [ ] 2.1 (P) 設問保存での選択肢画像の読み書きとスナップショット反映
  - 設問の保存・取得で、選択肢ごとの画像参照を扱えるようにする。保存時は画像の差し替え・削除が新しい値で表現され、設問画像との併用も保たれる
  - 選択肢のテキストは画像の有無にかかわらず従来どおり必須で、空の場合は保存を拒否する
  - 開催開始時に凍結される設問スナップショットに、選択肢の画像参照が含まれる
  - 画像付き選択肢を保存して取得すると画像参照が往復して一致し、画像なしの既存形式の設問は変更なしで保存・取得できることを統合テストで確認する
  - _Requirements: 1.1, 1.2, 1.4, 1.5, 1.6, 1.7, 1.8, 6.1, 6.4_
  - _Boundary: CatalogRepository_
  - _Depends: 1.1_

- [ ] 2.2 (P) 開催中の凍結スナップショットの正規化
  - 画像参照を持たない古い形式の凍結スナップショットを読み出した場合、各選択肢の画像参照を「なし」として扱う
  - 古い形式のスナップショットで開催中のイベントが、出題・正解発表を通して従来どおり進行できることを確認する
  - 新しい形式のスナップショットが、画像参照を保ったまま保存・読み出しできることを確認する
  - _Requirements: 6.3, 6.4_
  - _Boundary: live-store_
  - _Depends: 1.1_

- [ ] 2.3 (P) 選択肢画像の配信・検証が既存のメディア基盤で成立することの確認
  - 加工後の画像が、既存のアップロード(形式とサイズ上限の検証)を通って保存され、設問画像と同じ検証が適用されることを確認する
  - 主催者のセッション・参加者トークン・投影トークンのいずれでも画像が取得でき、認可のない要求や別イベントの要求は拒否されることを確認する
  - サイズ上限を超える画像がアップロード時に拒否されることを確認する
  - 既存のメディア配信の仕様を変更せずに、これらの確認テストが通る
  - _Requirements: 2.7, 2.8, 7.1, 7.2, 7.3, 7.4_
  - _Boundary: MediaApi_
  - _Depends: 1.1_

- [ ] 3. コア: 画像の自動統一
- [ ] 3.1 (P) 中央トリミング・縮小・JPEG化の画像加工
  - 選択された画像を、固定アスペクト比へ中央トリミングし、長辺を上限以下に縮小して、JPEGとして返す。元画像が小さい場合は拡大しない
  - 画像の向き情報を反映し、透過部分は白で塗りつぶす。トリミング位置の手動調整は行わない
  - 許可されない形式のファイルや、読み込み・加工に失敗した場合は、成功ではなく失敗の種類を返し、加工後の画像を生成しない
  - トリミング矩形と出力寸法の計算を純粋関数として単体テストし、横長・縦長・正方形・小さな画像で、比率4:3・上限以下・拡大なしとなることを確認する
  - _Requirements: 2.1, 2.2, 2.3, 2.5, 2.6_
  - _Boundary: ImageProcessor_
  - _Depends: 1.2_

- [ ] 4. コア: 投影画面での選択肢画像表示
- [ ] 4.1 (P) 画像付き選択肢の表示部品と出題表示のフィットレイアウト
  - 画像付き選択肢の1件分(画像とテキストを同じ枠として対応づけた表示)の部品を用意する。画像の領域は読み込み前から確保し、読み込みに失敗した場合は画像のみを隠してテキストを表示する
  - いずれかの選択肢が画像を持つ設問のときだけ、出題表示を、スクロールを発生させず画面内に収まる専用レイアウトに切り替える。2択は2列、4択は横1列で並べ、設問画像がある場合も同時に表示する
  - 画像のない選択肢が混在する場合も、すべての選択肢が収まる。文言のみの設問は従来のレイアウトのまま変わらない
  - 画像付き2択・4択、設問画像の併用、混在、読み込み失敗の各ケースで、基準サイズの画面内に内容が収まりスクロール要素が生じないことをUIテストで確認する
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 3.5, 3.6, 3.7, 3.8, 3.9_
  - _Boundary: OptionTile, QuestionView_
  - _Depends: 1.1, 1.2_

- [ ] 4.2 正解発表表示での選択肢画像と内訳の両立
  - 進行画面と投影画面で共通の内訳行に、選択肢の画像参照を含める
  - 画像付き設問の正解発表で、正解の選択肢を画像とともに従来と同じ強調(枠・「正解」表示)で表示し、他の選択肢は減光する。各選択肢の回答数と割合を、画像と両立して画面内に表示する
  - 画像付き設問の正解発表も、スクロールなしで画面内に収まる。画像のない設問の正解発表は従来の表示のまま変わらない
  - 画像付き2択・4択の正解発表で、正解の画像・強調・回答数と割合が表示され、基準サイズの画面内に収まることをUIテストで確認する
  - _Requirements: 4.1, 4.2, 4.3, 4.4, 4.5_
  - _Boundary: RevealView, option-breakdown_
  - _Depends: 4.1_

- [ ] 5. コア: 主催者の設問エディタ
- [ ] 5.1 (P) 選択肢画像を含むフォーム検証と形式切替時の画像保持
  - フォームの選択肢が画像参照を持てるようにし、画像があってもテキストが空の選択肢は保存前に拒否して、該当する選択肢の位置を示す
  - 二択・四択の切り替え時に、残る選択肢の画像を保持し、追加される選択肢は画像なしにする
  - 画像付き・なしの選択肢で、テキスト空の拒否と、形式切替での画像保持が期待どおりになる単体テストが通る
  - _Requirements: 1.2, 1.4, 1.9_
  - _Boundary: question-validation_
  - _Depends: 1.1_

- [ ] 5.2 エディタでの選択肢ごとの画像の選択・確認・差し替え・削除
  - 設問の保存リクエストに選択肢ごとの画像参照を含める。画像を選んだら加工(3.1)してからアップロードし、得られた参照をその選択肢に設定する
  - 加工後の画像を、選んだ選択肢の位置でその場に確認できるようにし、差し替え・削除もできるようにする。2択・4択のどちらでも使え、設問画像とも併用できる
  - 非対応の形式、読み込み・加工の失敗、サイズ上限超過の場合は、該当する選択肢の位置にその旨を表示し、その選択肢の画像は変更しない
  - 画像を選択してアップロード・表示・保存でき、差し替えと削除、失敗時に状態が変わらないこと、テキスト空の選択肢が保存されないことをUIテストで確認する
  - _Requirements: 1.1, 1.3, 1.4, 1.5, 1.6, 1.7, 1.8, 2.4, 2.5, 2.6, 2.7_
  - _Boundary: QuestionEditor_
  - _Depends: 2.1, 3.1, 5.1_

- [ ] 6. コア: 設問単位のプレビュー
- [ ] 6.1 (P) プレビュー下書きの受け渡し
  - 編集画面からプレビューへ、設問文・解説・設問画像・選択肢(テキスト・画像・正解)の下書きを渡す仕組みを用意する。プレビュー側は起動時に下書きを要求でき、編集側は変更のたびと要求への応答で最新の下書きを送る
  - 編集側がフォームを閉じたときに、閉じたことを通知する。受信するメッセージは形式を検証し、不正なものは無視する
  - イベントと編集の開始ごとに識別できる経路を使い、複数の編集・プレビューが混ざらないようにする
  - 下書きの要求に最新の内容が返ること、変更が購読側へ届くこと、閉じた通知が届くこと、不正なメッセージが無視されることをテストで確認する
  - _Requirements: 5.2, 5.3, 5.8_
  - _Boundary: question-preview-channel_
  - _Depends: 1.1_

- [ ] 6.2 プレビュー枠の共有化と既存プレビューへの選択肢画像の対応
  - 既存のプレビューにある「基準サイズで実寸描画して縮小表示する枠」を、既存の通し確認プレビューと新しい設問単位プレビューが共有できる部品として切り出す
  - 既存の通し確認プレビューが、選択肢画像のある設問を実画面と同じ部品で表示できるようにする
  - 既存の通し確認プレビューの動作と見た目が変わらず、既存のプレビュー関連テストがすべて通ることを確認する
  - _Requirements: 5.5, 5.6, 5.9_
  - _Boundary: PreviewStageFrame, ThemePreviewWalkthrough_
  - _Depends: 4.2_

- [ ] 6.3 設問単位プレビューのページとルート
  - 新しいタブで開く設問単位プレビューのページと、そのためのホスト用ルートを追加する
  - 起動時にイベントの外観(配色・ロゴ・背景)を取得し、下書きを受けて、実際の投影画面と同じ部品・外観・縦横比で、出題表示と正解発表表示を切り替えて表示する。下書きは保存しない
  - 一定時間(3秒)下書きを受け取れない場合、または編集側が閉じられた場合は、理由を表示して誤った内容を出さず、直前の内容も消す。ブラウザが対応していない場合もその旨を表示する
  - 下書きの受信で描画されること、編集側の変更が反映されること、応答なしと閉じた通知で取得不可の表示になること、画像付き設問が実画面と同じ構成で描画されることをUIテストで確認する
  - _Requirements: 5.1, 5.2, 5.3, 5.4, 5.5, 5.6, 5.7, 5.8_
  - _Boundary: QuestionPreviewPage_
  - _Depends: 6.1, 6.2_

- [ ] 7. 統合: 画面間の結線
- [ ] 7.1 投影画面で選択肢画像を取得して表示する結線
  - 投影画面が、受信した設問の選択肢画像参照から、投影トークン付きの画像URLを組み立てて出題表示・正解発表表示へ渡す
  - 画像付き設問の出題から正解発表までを、投影画面で通して表示でき、画像のない設問は従来どおり表示されることを確認する
  - _Requirements: 3.1, 3.5, 4.1, 4.2, 6.1_
  - _Boundary: StageApp_
  - _Depends: 4.2, 2.1_

- [ ] 7.2 エディタからプレビューを開く導線と下書きの公開
  - 設問編集フォームに「プレビューを開く」操作を追加し、編集の開始ごとに識別子を採番して、その設問だけのプレビューを新しいタブで開く
  - フォームの内容が変わるたびに最新の下書きを公開し、フォームを閉じる・保存して閉じるときは閉じたことを通知する。ブラウザが対応していない場合は操作を無効にして理由を表示する
  - 編集中の未保存の内容(選択肢画像を含む)が、開いたプレビューに反映され、編集の変更が開き直さずに反映されることを確認する
  - _Requirements: 5.1, 5.2, 5.3, 5.8_
  - _Boundary: QuestionEditor_
  - _Depends: 5.2, 6.3_

- [ ] 8. 検証
- [ ] 8.1 保存から配信までの通し統合テスト
  - 画像付き選択肢を持つ設問を保存し、開催開始後のスナップショットと、投影画面向けWebSocketの設問データに画像参照が現れることを実際のデータベースと接続で確認する
  - 画像なしの既存形式の設問が、保存・出題・正解発表・採点・ランキングを通して従来どおり動作し、画像の有無で採点とフェーズ遷移の結果が変わらないことを確認する
  - 画像参照を持たない古い形式の凍結スナップショットで開催中のイベントが完走できることを確認する
  - _Requirements: 6.1, 6.3, 6.4_
  - _Depends: 2.1, 2.2, 7.1_

- [ ] 8.2 実ブラウザでの収まり確認と調整
  - 4択に設問画像と長い問題文を組み合わせた最も厳しい条件を含め、2択・4択、混在、設問画像の併用で、基準サイズの投影画面にスクロールなしで全要素が収まることを実際のブラウザで確認する
  - 画像が極端に小さくなる場合は、画像仕様の比率や領域の配分を調整し、再度確認する
  - 設問単位プレビューが実際の投影画面と同じ見た目になっていることを、同じ設問を並べて確認する
  - 確認した条件と結果(必要なら調整内容)が記録され、全条件で収まりが成立している
  - _Requirements: 3.2, 3.3, 3.4, 3.7, 4.4, 5.5, 5.6_
  - _Depends: 7.1, 7.2_
