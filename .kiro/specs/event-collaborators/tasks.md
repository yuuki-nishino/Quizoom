- [x] 2. コア: 共同運営者リポジトリ(Collaborator Repository)
- [x] 2.1 招待の発行と重複・自己招待の拒否
  - メールアドレスの正規化(trim + lowercase)を行った上で招待を作成し、`crypto.randomUUID()`による推測困難な招待トークンを発行する
  - 同一メールアドレスへの未失効の招待が既に存在する場合(`pending`または`accepted`)は`ALREADY_COLLABORATOR`を、招待対象が所有者自身のメールアドレスの場合は`SELF_INVITE`を返す
  - 観測可能な完了条件: 同一メールアドレスへ2回目の招待作成を試みると`ALREADY_COLLABORATOR`が返り、行が重複登録されないことを確認できる。所有者自身のメールアドレスでの招待作成が`SELF_INVITE`で拒否されることを確認できる
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.6, 6.1_
  - _Boundary: CollaboratorRepository_

- [x] 2.2 招待情報の取得と受諾
  - 招待トークンから招待情報(イベントID・イベントタイトル・招待先メールアドレス)を取得する内部向け関数を実装する
  - 受諾処理では、ログイン中利用者のメールアドレスと招待先メールアドレスの一致を検証し、一致する場合のみ対象行を`status = accepted`・`user_id`設定・`accepted_at`記録の状態へ更新する
  - 失効済み(受諾済みまたは取消済みで存在しない)・存在しない招待トークンへのアクセスは`INVITE_INVALID`として扱う
  - 観測可能な完了条件: 招待先と異なるメールアドレスでの受諾試行が`EMAIL_MISMATCH`を返し対象行が更新されないこと、一致する場合は`status`が`accepted`になり同一トークンでの再受諾が`INVITE_INVALID`になることを確認できる
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5_
  - _Boundary: CollaboratorRepository_

- [x] 2.3 共同運営者の一覧・解除・招待取消・離脱
  - 受諾済み共同運営者と未受諾の招待を区別して一覧取得する関数、指定した共同運営者・招待をそれぞれ削除する関数、呼び出し利用者自身の行のみを削除する離脱関数を実装する
  - 観測可能な完了条件: 解除操作の実行後、対象共同運営者の行が削除されアクセス判定(2.4で実装)が`false`を返すようになることを確認できる。離脱関数が呼び出し利用者自身以外の行を削除しないことを確認できる
  - _Requirements: 5.1, 5.2, 5.3, 5.4, 5.5_
  - _Boundary: CollaboratorRepository_

- [x] 2.4 アクセス可否判定用の内部インターフェース
  - 指定した利用者が指定イベントの受諾済み共同運営者かどうかを返す関数と、指定した利用者が共同運営者として受諾済みのイベントID一覧を返す関数を実装する。これらは`event_collaborator`テーブルへアクセスする唯一の窓口とする
  - 観測可能な完了条件: 受諾済みの共同運営者について判定関数が`true`を返し、2.3の解除操作の後は`false`を返すことを確認できる
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 3.5_
  - _Boundary: CollaboratorRepository_
