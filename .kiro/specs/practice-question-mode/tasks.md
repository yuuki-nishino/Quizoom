# Implementation Plan

- [ ] 1. 基盤: 固定テスト問題の定義とイベント設定の下地
- [x] 1.1 固定テスト問題データとイベント設定モデルの拡張
  - 2択または4択・制限時間・正解・解説を持つ固定のテスト問題データを、他のどのドメインからも一意に参照できる形で定義する
  - イベントのメタ情報（開催中セッションへ引き渡される情報）にテスト問題モードの有効/無効を表す項目を追加する
  - 型チェックが通り、固定テスト問題データが選択肢2〜4件・正解ちょうど1件という既存の設問バリデーション規則を満たすことを確認する
  - _Requirements: 2.1, 2.2, 1.1_

- [x] 1.2 イベントのテスト問題モード設定を永続化するデータベース変更
  - イベント単位でテスト問題モードの有効/無効を保存できるようデータベーススキーマを拡張する（既定値は無効）
  - ローカル環境のデータベースへマイグレーションを適用し、既存イベントの読み込みが引き続き成功することを確認する
  - _Requirements: 1.1, 1.2_

- [ ] 2. コア: イベント設定の管理（カタログドメイン）
- [x] 2.1 (P) テスト問題モード設定の読み書きAPI
  - 主催者がイベント単位でテスト問題モードの有効/無効を切り替えられるようにする
  - 新規作成イベントのテスト問題モードは既定で無効になることを確認する
  - イベントが開催中の間は、テスト問題モードの変更のみが拒否され、他の設定項目（タイトル等）の変更には影響しないことを確認する
  - イベント情報を取得した際に、現在のテスト問題モードの設定値が含まれることを確認する
  - 単一イベントの現在のテスト問題モード設定値だけを軽量に取得できる手段を用意し、セッション実行部（後続タスク3.2）から呼び出せるようにする
  - _Boundary: Catalog Repository_
  - _Requirements: 1.1, 1.2, 1.3, 1.4_

- [x] 2.2 公開時にテスト問題モード設定をセッションへ引き継ぐ
  - イベントを公開した際、そのイベントのテスト問題モード設定がセッション側に引き継がれ、進行ロジックから参照できることを確認する
  - _Depends: 2.1_
  - _Requirements: 1.1_

- [ ] 3. コア: テスト問題の進行ロジック（セッションドメイン）
- [x] 3.1 進行状態機械へのテスト問題分岐の追加
  - 待機状態から開始した際、テスト問題モードが有効なら本編最初の設問ではなく固定テスト問題が次に出題される対象になるようにする
  - テスト問題の出題・締切・正解発表という進行操作が、本編の設問と同じ一連の操作（出題する／締め切る／正解を発表する）で行えるようにする
  - テスト問題の正解発表が完了した後、本編最初の設問へ進む操作が提供されるようにする
  - テスト問題モードが無効な場合は、待機状態から開始した際に直接本編最初の設問が対象になり、テスト問題に関する進行操作は一切現れないことを確認する
  - 進行状態機械の単体テストで、テスト問題モードの有効/無効それぞれについて「待機→テスト問題（または本編）出題→締切→正解発表→本編最初の設問」の一連の遷移が期待通りになることを確認する
  - _Requirements: 3.1, 3.2, 3.4, 3.5, 3.7, 3.8_

- [x] 3.2 セッション実行部でのテスト問題出題・配信・開催開始時の設定再同期・採点除外の配線
  - テスト問題が出題・正解発表された際、投影画面・回答画面へ他の設問と同じタイミングで内容が配信されることを確認する
  - イベントの公開後・開催開始前にテスト問題モードの設定が変更された場合でも、開催を開始した時点の最新の設定値が進行に反映されることを確認する（公開時点の古い設定値のまま開催が始まらないこと）
  - テスト問題への回答が、正解数・合計回答時間の集計や中間/最終ランキングに一切反映されないことを確認する
  - 結果を確定した際、テスト問題への回答が結果アーカイブ（主催者が後から閲覧する設問別回答記録を含む）に一切保存されないことを確認する
  - 統合テストで、テスト問題出題→締切→正解発表→本編最初の設問への遷移→本編1問分の出題〜結果確定、という一連の操作を通しても、最終的な正解数・ランキング・アーカイブにテスト問題の影響が残らないことを確認する
  - _Depends: 2.1, 3.1_
  - _Requirements: 1.1, 1.3, 3.2, 3.3, 4.1, 4.2, 4.3, 4.4_

- [ ] 4. コア: 進行画面（主催者向けUI）
- [x] 4.1 (P) テスト問題の進行状況を判定する表示ロジック
  - 現在「テスト問題を出題できる状態」か「テスト問題の正解発表が完了し本編へ進める状態」かを、進行画面の表示状態から判定できるようにする
  - 判定ロジックの単体テストで、テスト問題モード無効時にはいずれの判定も真にならないことを確認する
  - _Boundary: LiveConsole state_
  - _Requirements: 3.1, 3.7, 3.8_

- [x] 4.2 進行画面の操作導線をテスト問題向けに出し分け
  - 待機直後の出題操作が、テスト問題出題時には本編の出題とは異なる文言で表示されることを確認する
  - テスト問題の正解発表完了後は、中間ランキング表示・結果確定の操作を隠し、本編最初の設問へ進む操作のみを表示することを確認する
  - テスト問題モードが無効な開催では、これらのテスト問題向け表示が一切現れないことを確認する
  - _Depends: 4.1_
  - _Requirements: 3.1, 3.7, 3.8_

- [x] 4.3 (P) イベント編集画面でのテスト問題モード切り替えUI
  - 主催者がイベント編集画面からテスト問題モードの有効/無効を切り替えられ、現在の設定値が表示されることを確認する
  - イベントが開催中の間は切り替え操作が無効化され、変更できないことを確認する
  - _Boundary: PublishPanel_
  - _Requirements: 1.1, 1.3, 1.4_

- [ ] 5. コア: 投影画面・参加者画面
- [x] 5.1 (P) 待機状態への簡易ルール説明の表示
  - 投影画面の待機状態に、選択式で回答し正解数と回答時間で最終順位が決まることを説明する文言が表示されることを確認する
  - この文言が、テスト問題モードの有効/無効に関わらず常に表示され、既存のイベントタイトル・参加用QRコード・参加者数の表示を隠さないことを確認する
  - _Boundary: WaitingRoom_
  - _Requirements: 5.1, 5.2, 5.3_

- [ ] 5.2 (P) 投影画面でのテスト問題の明示
  - 出題中・正解発表中の投影画面で、表示中の内容がテスト問題であることが一目でわかる表示になっていることを確認する（本編設問の「第N問」表示等と混同しないこと）
  - _Boundary: QuestionView, RevealView_
  - _Requirements: 3.3, 3.6_

- [ ] 5.3 (P) 回答画面でのテスト問題の明示と練習完了表示
  - 出題中の回答画面で、表示中の内容がテスト問題であることが一目でわかる表示になっていることを確認する
  - テスト問題の正解発表時は、本編と同じ正解数・順位の数値を表示せず、テスト問題であり採点に反映されない旨の案内と正誤のみを表示することを確認する
  - _Boundary: AnswerScreen, ResultScreen, PlayerApp_
  - _Requirements: 3.3, 3.6_

- [ ] 6. 統合と検証
- [ ] 6.1 テスト問題モードを通した進行の結合確認
  - テスト問題モードを有効化したイベントで、開始から「テスト問題出題→締切→正解発表→本編最初の設問出題」までを主催者操作で一通り実施し、投影画面・回答画面が各段階で期待通りの内容（テスト問題の明示、正解表示等）を表示することをブラウザで確認する
  - テスト問題モードを無効化したイベントでは、テスト問題に関する表示・操作が一切現れず、開始直後から本編最初の設問に進むことを確認する
  - _Depends: 3.2, 2.2, 4.2, 4.3, 5.1, 5.2, 5.3_
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 3.5, 3.6, 3.7, 3.8, 5.1, 5.2, 5.3_

- [ ] 6.2 採点・結果アーカイブからの除外の最終確認
  - テスト問題に複数の参加者が異なる正誤で回答した状態から本編を最後まで進めて結果を確定し、最終ランキング・共有ページ・主催者向け結果閲覧のいずれにもテスト問題の回答が影響・出現しないことを確認する
  - _Depends: 3.2_
  - _Requirements: 4.1, 4.2, 4.3, 4.4_

- [ ] 6.3 全体回帰確認
  - 型チェック・既存テストスイート全体・ビルドが全て成功することを確認する
  - _Depends: 6.1, 6.2_
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 2.1, 2.2, 3.1, 3.2, 3.3, 3.4, 3.5, 3.6, 3.7, 3.8, 4.1, 4.2, 4.3, 4.4, 5.1, 5.2, 5.3_
